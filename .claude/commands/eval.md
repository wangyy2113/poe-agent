先读 `tests/golden/BASELINE.md` 拿到当前基线，再跑：

```bash
.venv/bin/python scripts/eval_run.py          # 检索侧，离线
.venv/bin/python scripts/eval_run.py --gate   # 出口闸门，录制回放，离线
.venv/bin/python scripts/eval_run.py --audit  # 人工审计指标（读 audit.yaml 里已填的结论）
```

然后**逐项与基线对比**，报出变化的方向与幅度。

## 判读规则（这几条比数字本身重要）

- **错误拒答率与无据漏出率必须成对报告。** 只压一头不算完成：收紧规则会抬高错误拒答，
  放宽会让推断重新漏出。任何一侧改善都要同时说另一侧有没有退。
- **流式与批量判定必须 100% 一致。** 这条是不变量，不是指标——掉下来就是 bug，
  优先级高于任何比率的改善。「仅空白字符不同」单列，不算失败。
- **`--audit` 的三项是抽样结果**，分母就是已判条数。报的时候必须带分母与判定人，
  不要写成全量结论。
- **blocked 池是「当前仍被拦的句子」**，每修好一类误拦，池子成分就变——
  所以错误拒答率不能跨轮次直接比绝对值。跨轮次看**拦截总数**与**已修类别数**。
- 指标是 0 或异常整齐时，**先怀疑量错了**，再怀疑功能坏了（这个项目已经踩过两次：
  工具名取错键让路由指标恒为 0；新鲜度用整体指纹比对让所有录制被误报过期）。

## 什么时候需要重录

`--record` 会发真实请求、**消耗 token**，所以它不在允许列表里，会向你确认。只有这两种情况需要重录：

1. 改动影响了**哪些用例能进入生成**（检索判定、工具路由、维度闸门）；
2. 回放报「录制过期」——证据正文变了。

只改出口闸门的判定规则**不需要重录**：回放用的就是录制里模型的原始正文，
那正是录制回放机制存在的理由。重录前先算清哪些用例受影响，只重录那些。
